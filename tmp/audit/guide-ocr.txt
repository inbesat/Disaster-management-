polygons In JS this would mean loading every geometry
into memory.

Al / LLM / RAG System
8.1 What "multi-agent" means here — no jargon
Imagine an assembly line, not a team of genius robots. A box comes in labeled "district =
Patna, disaster = flood, rainfall = 21 0 mm". Five workers stand in a line, each doing one
simple job:
1. Worker 1 (predictor) stamps a risk label: SAFE / WATCH / HIGH / CRITICAL.
2. Worker 2 (planner) writes the plan: evacuate these blocks, open these shelters.
3. Worker 3 (allocator) decides which boats, buses, and kits go where.
4. Worker 4 (validator) checks the plan isn't nonsense.
5. Worker 5 (communicator) runs only after a human approves — it fires the alerts.
That assembly line is a LangGraph — a graph where each node is one worker and you can
inspect the state at every step. In code: defines

8.5 Five likely viva questions about the Al layer
Q. Why not just call one LLM directly instead of LangGraph?
The response-planning flow must be auditable and deterministic in its critical decisions.
LangGraph gives a fixed pipeline where every node is a single job, state is inspectable at
each step, and — crucially — risk labels and plan validation are rule-based, so no LLM
can hallucinate "evacuate" or "all clear". The LLM is reserved for open-ended chat where
tools keep it grounded in DB facts.
Q. How do you prevent the Al from hallucinating wrong emergency advice?
Four layers: (1) the chat model must call tools to see real data; (2) RAG context is
injected via
so answers quote documents; (3) every response is
district-scoped by
lib/security/tool-logger . ts
Q. What happens if all your LLM providers are down at once?
The chain steps down Groq -9 OpenRouter Bluesminds, then AIBridge hands off to
on-device Gemma via WebLLM, then to the 61 -rule fallback. The alerting path never
depends on an LLM at all — it's deterministic
Only conversational chat degrades.
Q. Why XGBoost for flood prediction and not a neural network?
Flood risk from hydrology is a small tabular problem — 4 engineered features,
thousands of rows at most. Boosted trees train in seconds on CPU, need no GPU or big

--- guide-20.png ---
dataset, and give interpretable feature importances — "why did the district go to High?"
is answerable with tree models, not with a neural net.
Q. How does RAG know which documents are relevant to a query?
Every chunk is embedded to 1 536 dimensions; the query is embedded the same way;
pgvector returns nearest chunks by cosine similarity HNSW). Top-k chunks feed
the prompt; without keys, keyword search takes over
so retrieval never fails silently.
How to explain this in a viva: "We built the Al as a layered system. The response
pipeline is a deterministic LangGraph — think assembly line, not autonomous agents —
because safety-critical decisions like 'evacuate' must be explainable and can never be
hallucinated. The LLM is used where open-ended reasoning is needed, grounded by
RAG over SOP documents and forced through tools that can only see real database
data. Every layer has a fallback, down to a rule-based engine, so the system degrades
gracefully instead of dying."
